* Circuit

[[https://github.com/Kiyomi-Computation-Systems/circuit/actions/workflows/ci.yml][https://github.com/Kiyomi-Computation-Systems/circuit/actions/workflows/ci.yml/badge.svg]]

An HTTP abstraction layer in the manner of [[https://github.com/ring-clojure/ring][Ring]] for R6RS Scheme.

#+begin_quote
✨ *AI Disclosure:* LLMs are used extensively in the planning and development of this project.
#+end_quote

** Requirements

- Linux or macOS, on x86-64 or arm64
- Chez Scheme 10.4.1 or later, built with threads
- libuv 1.48 or later that ~pkg-config~ can see, and a C compiler: the
  server's libuv binding builds a small C shim

Circuit runs on [[https://github.com/Kiyomi-Computation-Systems/chez-http-server][chez-http-server]], pinned under ~vendor/~.

** Status

Early. Requests, responses, middleware, the adapter onto the server, the middleware
that knows the server's waits (a catch for errors, a timeout, request logging), and
upgrades work. A router and WebSockets are still to come.

** Build and test

#+begin_src sh
git clone https://github.com/Kiyomi-Computation-Systems/circuit.git
cd circuit
make submodules   # clones the pinned server and what it needs
make test         # builds the libuv shim, then runs every tests/test-*.sps
#+end_src

On a Guix host, run builds and tests in the pinned container:
~scripts/guix-env make test~. ~make help~ lists every target.

** Quick start

A handler takes a request and gives back a response:

#+begin_src scheme
(import (rnrs) (circuit) (circuit http-server))

(run-server
 (lambda (req)
   (make-res 200 '(("content-type" . "text/plain")) "hello\n")))
#+end_src

~make run PROGRAM=examples/hello.sps~ runs it on ~127.0.0.1:8080~. [[file:examples/README.md][examples/]] has more:
reading a body, streaming, and a handler that waits.

Middleware takes a handler and gives back one. ~wrap~ puts the last outermost.
~(circuit middleware waits)~ has three:

#+begin_src scheme
(import (rnrs) (circuit) (circuit http-server) (circuit middleware waits))

(run-server (wrap app wrap-catch (wrap-timeout 5000) wrap-log))
#+end_src

- ~wrap-catch~ turns a raise into an empty ~500~, and logs a ~handler-failed~ line, as
  the server does. ~(wrap-catch handler on-raise)~ answers with your own response
  instead.
- ~wrap-timeout~ answers an empty ~504~ when its milliseconds pass while the handler
  waits, reading the body included. Put it outside ~wrap-catch~, so an ~on-raise~ that
  waits still gets a ~504~.
- ~wrap-log~ logs a line on standard output once each response is done:
  ~request GET /users/7 200 written 3~, the last number in milliseconds. The status is
  the handler's: ~failed~ means the server ended it, perhaps with its own. A request the
  server refuses before any handler runs, such as a ~413~ for a body past its cap, isn't
  logged.

A handler can take the connection over for another protocol. ~(make-upgrade-res headers
take-over)~ answers ~101~, then the server calls ~(take-over transport retained)~:
~retained~ holds the bytes the server had already read past the request, and the
transport is how you read and write from then on (~transport-write!~,
~transport-read-start!~ and the rest, from ~(circuit http-server)~). To wait, the
take-over answers ~(awaiting thunk)~. [[file:examples/upgrade.sps][examples/upgrade.sps]] echoes every byte back.
Middleware can change an upgrade's headers, but not its status or body:
~res-upgrade-body?~ tells one apart, and ~make-upgrade-res~ around
~res-upgrade-body-take-over~ wraps its take-over.

** Configuration

Settings come from the environment. The server's are its own ~CHEZ_HTTP_~ variables
(where it listens, its limits; see its [[https://github.com/Kiyomi-Computation-Systems/chez-http-server/blob/v0.9.0/docs/configuration.md][configuration]]). Circuit adds one:

| Variable                   | Default | What it sets                                                               |
|----------------------------+---------+----------------------------------------------------------------------------|
| ~CIRCUIT_PORT_PIECE_BYTES~ |   65536 | the most a piece of a port body holds; a port this size or less goes whole |

The server caps no request body by default: an app that reads one whole should set
~CHEZ_HTTP_MAX_BODY_BYTES~.
