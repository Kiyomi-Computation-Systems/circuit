* Circuit

[[https://github.com/Kiyomi-Computation-Systems/circuit/actions/workflows/ci.yml][https://github.com/Kiyomi-Computation-Systems/circuit/actions/workflows/ci.yml/badge.svg]]

An HTTP layer in the manner of [[https://github.com/ring-clojure/ring][Ring]] for R6RS Scheme, on [[https://github.com/Kiyomi-Computation-Systems/chez-http-server][chez-http-server]].

#+begin_quote
✨ *AI Disclosure:* LLMs are used extensively in the planning and development of this project.
#+end_quote

** Features

- *Handlers are procedures.* A handler takes a request and returns a
  response, and a middleware takes a handler and returns a new one. ~wrap~
  stacks them (see [[file:docs/middleware.md][docs/middleware.md]]).
- *Bodies as ports, both ways.* A request's body is a port, read as it
  arrives and capped where you say. A response streams from a port or a
  producer, server-sent events included (see [[file:docs/bodies.md][docs/bodies.md]]).
- *Handlers that wait.* Each request runs on a coroutine of its own, so a
  handler can sleep, wait for another request, or give up at a deadline (see
  [[file:docs/waiting.md][docs/waiting.md]]).
- *A router.* By the path, then the method. A word beats a parameter whatever
  the table's order, and groups and mounts take middleware of their own (see
  [[file:docs/routing.md][docs/routing.md]]).
- *Middleware for the waits.* A catch for errors, a timeout and a request
  log (see [[file:docs/middleware.md][docs/middleware.md]]).
- *Upgrades and WebSockets.* A handler can take the connection over, or
  answer a WebSocket handshake through [[https://github.com/Kiyomi-Computation-Systems/chez-websocket][chez-websocket]] (see
  [[file:docs/upgrades.md][docs/upgrades.md]]).
- *Handlers tested without a server.* ~make-test-req~ makes a request to
  call a handler with (see [[file:docs/testing.md][docs/testing.md]]).
- *A plain R6RS core.* Requests, responses, headers, middleware and the
  router are portable R6RS. Only the adapter and the waits' middleware use
  Chez's own procedures.

v0.1.1 is the latest release. The API may change in any release before 1.0;
[[file:CHANGELOG.md][CHANGELOG.md]] says what each release has.

** Quick start

#+begin_src scheme
(import (rnrs) (circuit) (circuit http-server))

(run-server
 (lambda (req)
   (make-res 200 '(("content-type" . "text/plain")) "Hello\n")))
#+end_src

Save it as ~hello.sps~ in the checkout, start it with
~make run PROGRAM=hello.sps~, and ~curl http://127.0.0.1:8080/~. The
[[file:docs/quickstart.md][quickstart]] goes on from there. The documentation starts at
[[file:docs/README.md][docs/README.md]], also published at
[[https://kiyomi-computation-systems.github.io/circuit/][kiyomi-computation-systems.github.io/circuit]].

** Build and test

You need Linux or macOS, on x86-64 or arm64, with:

- Chez Scheme 10.4.1 or later, built with threads
- libuv 1.48 or later that ~pkg-config~ can see, and a C compiler: the
  server's libuv binding builds a small C shim

Circuit runs on [[https://github.com/Kiyomi-Computation-Systems/chez-http-server][chez-http-server]], and takes WebSockets from
[[https://github.com/Kiyomi-Computation-Systems/chez-websocket][chez-websocket]], both pinned under ~vendor/~.

#+begin_src sh
git clone https://github.com/Kiyomi-Computation-Systems/circuit.git
cd circuit
make submodules   # clones the pinned server, what it needs, and chez-websocket
make test         # builds the libuv shim, then runs every tests/test-*.sps
#+end_src

~make help~ lists every target, and [[file:docs/installing.md][docs/installing.md]] has the rest: a Guix
host, building a release, running a program of your own.

~make site~ renders ~docs/~ into ~build/site/~, the pages GitHub Pages
publishes for each release. It needs the system *cmark-gfm* library (~brew
install cmark-gfm~ or ~apt install cmark-gfm~), and ~make site-deps~, run
once where there is a network. ~make check-site~ fails on a broken link or
anchor.
